# Content gaps

These are pages whose **structure** is sound but whose **substance** is thin, and where the missing material can only come from Graphxify's real work. Nothing below was written into the site; every item needs facts only Daniel has.

## Service pages

All four have: a clear H1, an intro, deliverables, "best for" / typical project / outcome, related work, related reading, an FAQ (visible HTML, no FAQ schema) and a CTA. What's missing:

| Service page | Gap | What to add (from real experience) |
|---|---|---|
| All four | **No proof on the page itself.** The "related work" cards link out, but no outcome, quote or number appears on the service page. | One short, real result per service (for example a client quote, or "launched in 3 weeks"). Only approved, true statements. |
| All four | Process shown only on /process | 2–3 sentences on how this service moves through the four stages, with a link to /process#stage-0X. |
| All four | No "what it costs / how it's scoped" guidance (pricing was removed deliberately) | Consider a factual "How projects are scoped" paragraph (tiers, what changes the price) without figures, if you still don't want to publish prices. |
| **CMS Architecture** | **No related case study at all.** It's the only service page without one. | A case study of a CMS build. This very site (custom Supabase CMS, roles, version history, ISR) is a genuine candidate, as is any client site whose team edits content themselves. |
| **Web Development** | Technologies are named only as "Next.js" | List the stack you really use (hosting, CMS options, analytics, forms), and why. |
| **Web Development** | "Lighthouse 90+" stated as a guarantee (see trust audit) | Replace it with measured scores from named, live client sites, or reword it as a target. |
| **Brand Systems** | Deliverables listed, but no example guideline pages | Show 2–3 real brand-guideline spreads from Maven or Luka Hair Salon (with permission). |
| **Web Design** | Accessibility claims (WCAG) without specifics | State which WCAG level you design to and what the pre-launch accessibility review checks. |

## Case studies (/works/*)

Rendered pages are **about 230–320 words**, with a single overview, challenge, approach, solution and result. For each project (see ENTITY-DATA-NEEDED §4 for the full list):

- Real, measured **outcomes** with source and timeframe (the biggest gap)
- **Client testimonial** with permission
- **Scope and deliverables** list (what was actually delivered: logo suite, 8-page site, CMS, and so on)
- **Technologies** used
- **Timeline** confirmation (years conflict between the CMS and code)
- **6 distinct images** with descriptive alt text (the gallery currently repeats images)
- A link to 1–2 **relevant articles** (for example healthcare sites → accessibility; FlyUp Line → mobile-first)
